# A linked run whose id is unknown

Read this when `mthds_run` refuses a run that sent a linked directory as `method_dir` beside the `method_id` of its `pipelex-method.json` with `pipelex.catalog.not_found`, before replying. Nothing was spent.

A linkage id the plane does not know refuses the run, and on a run that sent a folder beside the id, the problem's `code` is the discriminator rather than its wording: a rejected payload or a refused execution locus answers with a code of its own, located at `method_dir`, or at `files` when the files were listed, so only the unknown method answers `pipelex.catalog.not_found`, its `params` naming the id the API key's organization does not hold. The catalog is org-scoped, so a link made with another organization's key, or against another plane, reads exactly like a deleted method.

Report it with the `api_host` the link file records — that is what makes it diagnosable — and offer the same run **without** the id: it runs the very same bundle and loses only the history filing. Do not go looking for the bundle; the bundle was never in question.
