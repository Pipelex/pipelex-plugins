## Behaviour changes

Box G allows a phase to change behaviour only by resolving a contradiction found while consolidating, and by the deferrals the plan assigns to it. The plan assigns this skill no deferral. There is one contradiction.

1. **A photo of a receipt is recognised as a scanned document at step 1, where the refusal is decided.** Step 1 said "If the format is one this skill refuses (a photograph, handwriting), stop here with the refusal and the ask for a real file" (line 54), while `references/png.md` said "A brief that sounds like a photograph is sometimes a `document_scan` in disguise: 'a photo of a receipt' is a scanned document, and that recipe covers it. Read what the method actually does with the image before refusing." `png.md` is read at step 4, so a model following the skill refused at step 1 before it could read the sentence that told it not to. The ratified ruling (`docs/decisions.md`, "File synthesis is its own skill") ships `document_scan` and refuses `photograph`, which is what `png.md` says, so its sentence moves to the refusal in `SKILL.md` and leaves `png.md`: "A photo of a receipt or a form is a `document_scan`, which this skill makes; read what the method does with the image before refusing."

Not behaviour changes, but worth a reviewer's eye:

- **The venv rung is a reference.** Rung 2 is taken on a condition the model sees before it acts — the `uv` preflight fails and prints nothing, which `tests/recipes` pins as the silent fall-through — so the venv program, the runner line it yields and the substitution that must follow it move to `references/venv.md`, read before creating anything. The substitution caveat ("**substitute the absolute path this command printed**", silently wrong if skipped) is a caveat of that branch alone and moves with it, as `pipelex-design`'s stepwise-only rules moved with `stepwise.md`. What any machine needs stays in the skill: the venv's path, the guard that installing a *tool* always asks first, and the stop rows for a failed `python3 -m venv` and a missing `python3`. `tests/recipes/test_recipes.py` reads the venv block from `venv.md` now, and still creates, reuses and repairs the venv exactly as the skill says; its check that every reference block is a recipe or a template treats the venv reference as the environment's, holding exactly one block, the setup.
- **The placeholder check on `target` is a stop.** Every recipe opens with `assert "<" not in OUT and ">" not in OUT`, so a recipe run with `<output_dir>` still in its path stops with `OUT still holds a placeholder` rather than succeeding silently. The skill keeps "every `<…>` placeholder resolved" at the step that sets `OUT`, and the recovery is one row of the stop table.
- **Step 5 runs each reference's own verify command.** The PNG check the skill carried inline (with its kilobyte count) is now `png.md`'s verify block, which was the same command without the size; the PDF and Office checks were already their references'. The skill keeps what to expect of each format and the per-harness viewing sentence.
- **The size.** The Claude render lands at 10,580 characters (10,388 on Codex and on Vibe), down from 16,010 at this branch's base, under the phase's target of about 12,000. The only shared block the skill carries is the frontmatter, about 1,560 characters on Claude, most of it the description, which the design leaves out of scope. The read against the quotes below restored about 800 characters of qualifiers a tighter draft had lost.

The size diet's sixth phase rewrote `pipelex-synthetic-inputs` in the read-before-act shape: what it makes and refuses, its guards, the request, the environment's normal rung, the draft, the render, the verification and the report in `SKILL.md`, with a stop table; and the venv rung in a reference read when `uv` is absent. Most of the reasons the skill shipped were already recorded above, under "File synthesis is its own skill", and the skill now ships none of them. What follows is the rest. The paragraph-by-paragraph account of the move is `wip/skill-size-diet/classification-synthetic-inputs.md`.

- **The venv rung is a branch, read when `uv` is absent.** The `uv` preflight fails without a word when `uv` is not on `PATH`, which the recipe suite pins, so the model sees the condition before it creates anything, and `references/venv.md` carries the program, the runner line it yields and the substitution that must follow. The substitution — the absolute path the program printed, never `"$VENV/bin/python"`, which a fresh shell expands to `/bin/python`, present on some Linux distributions — is silently wrong when skipped, but only on that branch, so it travels with it. What every machine needs stays in the skill: the venv's path, the rule that installing a tool always asks first, and the stops for a missing `python3` and a failed `python3 -m venv`. `tests/recipes` runs the venv block from the reference.
- **The draft comes before the recipe.** The realism of a synthetic file is in what it says, not how it is drawn, so the skill has the content written in the reply before the recipe is opened, where the recipe's own sample content would otherwise anchor it.
- **Determinism holds within one environment, and only for content.** Every recipe seeds its randomness (`SEED`) and passes `invariant=1` to reportlab, so a rerun on the same machine with the same packages produces the same file, and an edit to the content block changes only the content. The packages are not pinned, and a different Pillow or numpy build can shift a PNG's pixels under the same seed, so two renders from different environments are compared by what they show, never by their bytes. Word and Excel files embed a creation timestamp neither library lets a caller fix, so two renders of the same content differ byte for byte even on one machine. Nothing the model does depends on the promise, so the skill says only to keep the seed and the flag.
- **A scanned page is the one output that can meet the storage limit.** `scannerize()` adds per-pixel grain, which is noise and does not compress, so an A4 `document_scan` at 150 dpi lands in the low megabytes while every other output is in the kilobytes. `/pipelex-inputs` treats the storage limit as terminal and never alters a file to fit it, so the size is read at verification, before the file is handed back, and `references/png.md` says how to render a smaller page.
- **A failed render removes only what it created**, so no `inputs.json` can point at a broken file, and no file the user already had is lost to a cleanup.
- **The placeholder check lives in the recipes.** `<` and `>` are legal filename characters, so a recipe still carrying `<output_dir>` would write into a real directory of that name, print success and exit 0. Every recipe asserts that its `OUT` holds neither character before writing, which makes the mistake a refusal rather than a silent success, and the skill's stop table says to set the real path and rerun.

## For the changelog

- `pipelex-synthetic-inputs` now fits in what Claude Code keeps of a skill after a compaction: the venv the skill builds when `uv` is absent is read from `references/venv.md` on that branch, and each recipe reference opens with the condition on which it is read.
