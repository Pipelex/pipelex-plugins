## Behaviour changes

Box G allows a phase to change behaviour only by resolving a contradiction found while consolidating, and by the deferrals the plan assigns to it. These are all of them, the third being an exception the orchestrating session ruled on.

1. **The `runs/` exclusion is stated once** (the deferral from phase 1's review, round 2). Step 1 of the old validation said "Gather **all** `.mthds` files in the bundle directory, none under a `runs/` directory" right beside the `validate-call` include, which states the same exclusion. Step 5 now says "Gather the bundle's files as the convention below says, the whole library", which is `pipelex-catalog`'s wording, and the include states the exclusion alone. The file set submitted is unchanged. The re-entry baseline keeps "read every `.mthds` file outside `runs/`", because that is the set the skill *reads*, which the submission convention does not govern — `pipelex-edit` and `pipelex-explain` word their reading step the same way.
2. **The stale-types search and the saved-copy notice are made at delivery, for whatever the run changed.** The old text ran the stale-types search only in the re-entry procedure's last step (line 246) and placed the saved-copy notice after that procedure (line 248), while `pipelex-organize`, when design invokes it, skips both "whose delivery step speaks for it" and "whose delivery step carries this notice too" (`templates/skills/pipelex-organize/SKILL.md.j2:110`, `:112`). So a converged stepwise construction that design handed to organize had neither said by anyone. Box R of the workspace-root `wip/plugin-skills-gaps/design.md` ratified that "the edit skills end their report with a saved-copy notice", which matches organize's reading, so both now sit in step 6. Both speak only when there is something to say — a sidecar naming the bundle's files, a link file beside the root — so a new design into a fresh directory hears nothing new; the change reaches a new design written into a directory that is already integrated or linked.
3. **The skill no longer carries the formatting-hook note** — an exception outside box G's two, ruled by the orchestrating session on 2026-09-23 so that the skill fits under the ceiling with room for review, and decided by the read-before-act test rather than by its size. Its sentence — every `.mthds` write triggers the validation hook, which lints, rewrites the file in canonical formatting and blocks on syntax errors; "just write the files — don't hand-format, and re-read a file before editing it again after the hook reformatted it" — is a stop by the read-before-act test, not a guard: the hook's own block names the syntax error, and the harness refuses an edit to a file changed since it was read (Claude Code's Edit, Codex's `apply_patch`, Vibe's edit tool), so a model that never read it pays one retry at most, and "don't hand-format" costs nothing when skipped. Ruled by the orchestrating session on 2026-09-23 over the alternative of moving the bundle-home rules to a reference read on every new design, which boxes B and H rule out. The content still lives in `docs/hooks.md` and in the include `pipelex-edit` and `pipelex-organize` carry; the plan's Deferred section gives phase 6 the same question for them.

Not behaviour changes, but worth a reviewer's eye:

- **The catalog-id bridge is read, not carried.** The bridge block (`catalog-id-bridge.md.j2`, about 1,930 characters rendered) is needed only when the target is a catalog id or a published address, a condition the skill sees before it acts, and it names a cross-skill hand-off that differs per harness. Box F set the pattern with `shared/credentials.md`, so the bridge is now a shared reference rendered per target, `skills/shared/catalog-id.md`, which includes the block unchanged; the block keeps one source. Approved by the orchestrating session on 2026-09-23 with four conditions, each met: the bridge's guards stay in `SKILL.md` at the pointer line and are registered; the reference opens with its entry condition and is generic, so `pipelex-edit` and `pipelex-organize` can point at it unchanged in phase 6; the plan's Deferred section carries that switch; and the reason is recorded here, in `docs/decisions.md` and in the plan. The pointer's condition names a published address as well as an id, because the bridge's last paragraph is what tells the model an address is not a target of this skill.
- **The bridge's two guards are stated in `SKILL.md` in their own words.** "Several hits are the user's choice, never yours" and "do not present the local files as the saved method's current content" are guards under box A — editing a comparison copy and presenting a local copy as the saved method are both silently wrong — so the Re-entry section states them at the pointer: "**When several directories are linked to the method, ask which is the work; never choose.**" and "**Never present a linked directory as the saved method's current content.**" The shared block keeps its own wording, because it is still included inline by `pipelex-edit` and `pipelex-organize`.
- **The saved-copy notice stays in `SKILL.md`, decided by the test and not by its size.** Its condition — a `pipelex-method.json` beside the root file — is visible before acting, so it could read as a branch; but its content is three guards: that the catalog does not have the change (silently wrong if unsaid), "**Offer that; never do it.**" (a save is a deployment) and "Never write or edit `pipelex-method.json`", the last two already registered. A guard never lives only in a file read on demand, so the notice stays. The stale-types notice stays too: its first sentence is the search step 6 runs, which is the main path, and it is an include `test_pipelex_integrate_skill.py` requires in design.
- **Stepwise is chosen as the complement of direct.** Step 3 states the direct criteria in full and says "**Stepwise** otherwise, for a large graph that benefits from independently valid review checkpoints, or on an explicit request for a scaffold, partial design, staged work, or a resumable intermediate result". The old stepwise list's first three signals (lines 115–117) are each the negation of a direct criterion — nested controllers against "no child is itself a controller, unless …", uncertain contracts, ownership, branching, iteration or wiring against "every branch, iteration, … and intermediate owner is decided", cross-branch shapes against "every … concept shape can be fixed from its consumers" — so they are not restated in `SKILL.md`; `stepwise.md` names all five signals in its opening sentence, which is its entry condition, and the pin on "nested controllers or multiple structural layers whose child contracts are not all fixed" moved there. The two signals that are not complements — the large graph and the explicit request — stay in step 3.
- **The size.** The Claude render lands at 12,899 characters (12,720 on Codex, 12,727 on Vibe) rather than the phase's target of about 12,000. Once the bridge and the formatting note left, the shared blocks design must still carry render to about 4,900 characters: the frontmatter (1,094), the saved-copy notice (1,098), the stale-types notice (798), the `validate-call` include (702), the requirements include (642), the `PipeFunc` warning twice (402) and the project-root markers (140). `pipelex-inputs` carried about 2,300. Before either move the fixed blocks were about 7,100 characters, and the main path box B and design section 5 keep in the skill — the contract, the bundle home, the mode choice, direct construction, the verdicts, the gate and delivery, the re-entry guards, the stops and the index — does not fit in much under 7,800 characters without dropping conditions, so no wording reached the ceiling without them. The read against these quotes then restored qualifiers worth about 215 characters, which is where the render ends.
