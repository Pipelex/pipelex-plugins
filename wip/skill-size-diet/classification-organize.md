# Classification — `pipelex-organize`

Phase 6 of the size diet ([`plan.md`](plan.md), [`design.md`](design.md) box A). Every paragraph, bullet and list item of `templates/skills/pipelex-organize/SKILL.md.j2` as it stood at `2fd7120` (the phase 1 landing; the template did not move between that commit and this phase's base, `e5287a5`), with its kind under the read-before-act rule and where it went. Line numbers are that version's. Read the rewrite against this table as a move: a row whose destination is the new `SKILL.md` names the section or step it landed in, and a row that left the shipped text names `docs/decisions.md` or the statement it duplicated.

The kinds are the design's — **guard**, **branch**, **stop**, **rationale** — plus **main path** for the steps themselves. "Duplicate" means the statement already lived in the named place, which now holds it alone. ## Behaviour changes

Box G allows a phase to change behaviour only by resolving a contradiction found while consolidating, and by the deferrals the plan assigns to it. These are all of them.

1. **The `runs/` exclusion is stated once** (the deferral from phase 1's review, round 2, assigned to this phase). Step 1 said "Gather **all** `.mthds` files in the bundle directory, none under a `runs/` directory" beside the `validate-call` include, which states the same exclusion. Step 1 now says "Gather the bundle's files as the convention below says", `pipelex-catalog`'s wording, as `pipelex-design` did in phase 4. Step 4's on-disk confirmation said "re-gather the directory's `.mthds` files outside `runs/`" and now says to validate "the bundle once more, gathered as in step 1", for the same reason. The file set submitted is unchanged. Step 4's deletion keeps its own "never one under a `runs/` directory", because that is a set the skill *deletes*, which the submission convention does not govern.
2. **The catalog-id bridge is read, not carried** (the deferral from phase 4). The bridge block (`catalog-id-bridge.md.j2`, about 1,930 characters rendered) left the skill for the shared reference `skills/shared/catalog-id.md`, which `pipelex-design` has read since phase 4 and which includes the block unchanged. Step 1 opens with the pointer, "**For a catalog id (`mt_…`) or a published address**, read [the catalog-id reference](../shared/catalog-id.md) before reading any file", placed so that the reference's "continue just after its pointer to this file" lands on the gather. The resume point was "**Step 1** of the procedure below", which is where the pointer's successor now is, so the model resumes at the same place. The bridge's two guards are stated at the pointer in the words `pipelex-design` uses, and registered: "**When several directories are linked to the method, ask which is the work; never choose.**" and "**Never present a linked directory as the saved method's current content.**"
3. **The skill no longer carries the formatting-hook note** (the deferral from phase 4, decided by the same test as for `pipelex-design`). The note — every `.mthds` write triggers the validation hook, which lints, rewrites the file in canonical formatting and blocks on syntax errors; "Don't hand-format, and re-read a file before editing it again after the hook reformatted it" — is a stop, not a guard. The hook's own block names a syntax error; the harness refuses an edit or an overwrite of a file changed since it was read (Claude Code's Edit and Write, Codex's `apply_patch`, Vibe's edit tool), so a model that never read the note pays one retry at most; and "don't hand-format" costs nothing when skipped. Organize meets the hook at exactly two points, both of which the steps already handle: step 4's confirmation re-validates what is on disk "since the hook may have reformatted what was written", and step 4's rollback rewrites files the hook reformatted, which the harness asks to be read first. `pipelex-edit` drops it too, so `templates/skills/shared/formatting-hook.md.j2` has no includer left. It is **not removed**: `tests/unit/test_gen_skill_docs.py::TestSharedSkillIncludes.SHARED_BLOCK_OWNERS` pins its sentence to it, and `docs/build-targets.md` (the shared-partials table) and `CLAUDE.md` (the repository structure, and "A block several skills say word for word lives in one include") still list it. Removing the partial, that entry and those two lines is one change for the orchestrating session.

Not behaviour changes, but worth a reviewer's eye:

- **The candidate is validated inline.** Step 3 says to call `mthds_validate` with the composed candidate set "inline, since nothing is written yet". The old step said "Prove equivalence before touching disk" and gave no form, while the `validate-call` include beside step 1 says to prefer the path form; a candidate that is not on disk has no path, so the inline fallback was the only form the old text allowed. The four words say so rather than leaving a model to reconcile the two.
- **Keeping the original contents is stated where it starts.** Step 4's rollback said "you still hold every original file's content from Step 1", which required step 1 to read and keep every file without saying so. The Guards section now says "**Keep every original file's content until the new layout is confirmed on disk**", and step 1 reads each file. Losing that content before a failed confirmation is the one unrecoverable outcome this skill can reach, so it is a guard and registered.
- **The two report notices share one condition.** The old step 5 said "**When invoked on its own rather than by `/pipelex-design`**" twice, once before the stale-types notice ("whose delivery step speaks for it") and once before the saved-copy notice ("whose delivery step carries this notice too"). It is said once, as "(whose delivery step carries both notices)", and the two notices are listed under it. The unit test that pinned the second parenthesis now pins the new one, in `test_gen_skill_docs.py::TestCatalogIdInEverySkill`.

## For `docs/decisions.md`

These bullets are ready to paste. They open a new section, **"`pipelex-edit`'s and `pipelex-organize`'s rationale, moved out of the skills (2026-09-23)"**, placed after "`pipelex-scaffold` drops the starters and runs its initializer branch through scripts"; `classification-edit.md` carries the bullets for edit in the same section. The section opens with this paragraph:

The size diet's sixth phase rewrote `pipelex-edit` and `pipelex-organize` in the read-before-act shape. Both keep their main path in `SKILL.md`, since every rule left in them is read on every run, and neither ships a reference of its own. Both made the same three moves, worded alike: the catalog-id bridge is read from the shared reference `pipelex-design` reads, the formatting-hook note left, and the `runs/` exclusion is stated once by the submission convention. Most of the reasons the two skills shipped were already recorded above, under "Edit vs design", "Classification comes before the verdict, and a trigger phrase has one owner", "Upload step in `pipelex-inputs`, and the light template stays pinned" and "A catalog id is a target in every skill", and the skills now ship none of them. What follows is the rest. The paragraph-by-paragraph account of the move is `wip/skill-size-diet/classification-edit.md` and `classification-organize.md`.

- **The catalog-id bridge is read, not carried, in all three file-based skills.** `pipelex-edit` and `pipelex-organize` point at `skills/shared/catalog-id.md` at the start of their step 1, as `pipelex-design` has since the diet's fourth phase, so the reference's "continue just after its pointer to this file" lands on the step's first act. Each states the bridge's two guards at its pointer in the words design uses, since a guard never lives only in a file read on demand. The move takes about 1,600 characters out of each skill, which is most of what brought organize under the ceiling. `catalog-id-bridge.md.j2` is now included by `catalog-id.md.j2` alone.
- **The formatting-hook note left the last two skills that carried it**, by the test that took it out of `pipelex-design`: it is a stop, because the hook's block names the syntax error it found and the harness refuses an edit or an overwrite of a file changed since it was read, so a model that never read the note pays one retry at most, and "don't hand-format" costs nothing when skipped. Organize keeps the one consequence it acts on as a half-sentence — its on-disk confirmation re-validates "since the hook may have reformatted what was written" — because a model that has just matched the candidate would otherwise plausibly skip the second call. The note's content lives in `docs/hooks.md`.
- **Organize regroups for comprehension, and fewer files is an effect, not the goal.** Signature-driven construction leaves a library correct but shaped by its history — one file per pipe, contracts duplicated as satisfied headers, and no relationship between the file layout and how the method reads. The skill regroups it the way source code is spread across files, so that a reader opens the root and then only the module they need; consolidation is the usual result, but a method with tens of pipes still needs several modules, and each file should read like a chapter, not a line. A single file is the degenerate case of a simple method.
- **A satisfied signature header is dropped and an unsatisfied one is kept.** A `PipeSignature` whose code has a concrete definition anywhere in the library is construction scaffolding the definition supersedes. One with no definition is a scaffold's backlog, and the validation verdict's `pending_signatures` is computed from it, so it is kept — deduplicated to one header per code — and the bundle stays its own todo list.
- **A layout the user asks for is honoured**, a single file or a grouping of their own, because the equivalence proof works the same for any layout: the verdict before and after is what the skill guarantees, and the grouping rules are its default, not a constraint.
- **Organize's candidate is validated inline.** The equivalence proof runs before anything is written, and a file that is not on disk has no path, so the submission convention's preferred path form cannot apply; the step says so rather than leaving a model to reconcile the convention with "before touching disk".
