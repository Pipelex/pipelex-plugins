# Classification — `pipelex-edit`

Phase 6 of the size diet ([`plan.md`](plan.md), [`design.md`](design.md) box A). Every paragraph, bullet and list item of `templates/skills/pipelex-edit/SKILL.md.j2` as it stood at `2fd7120` (the phase 1 landing; the template did not move between that commit and this phase's base, `e5287a5`), with its kind under the read-before-act rule and where it went. Line numbers are that version's. Read the rewrite against this table as a move: a row whose destination is the new `SKILL.md` names the section or step it landed in, and a row that left the shipped text names `docs/decisions.md` or the statement it duplicated.

The kinds are the design's — **guard**, **branch**, **stop**, **rationale** — plus **main path** for the steps themselves. "Duplicate" means the statement already lived in the named place, which now holds it alone. Each row quotes the conditions, qualifiers and remedies of what it classifies, in the source's words, and says so when its destination drops one and why.

The new `SKILL.md` keeps its scope split, a Requirements block, its mode table, steps 1 to 7 under their old headings, a stop table and a References index. It ships no reference of its own: the rename checklist is read on most runs and is a few lines, and every other rule is read on every run, so nothing met the test for a branch that pays for its pointer. It points at one shared reference, `skills/shared/catalog-id.md`, which `pipelex-design` already reads, and it no longer carries the catalog-id bridge block inline or the formatting-hook include. `pipelex-organize` made the same moves in the same phase ([`classification-organize.md`](classification-organize.md)), deliberately worded alike.

## Behaviour changes

Box G allows a phase to change behaviour only by resolving a contradiction found while consolidating, and by the deferrals the plan assigns to it. These are all of them.

1. **The catalog-id bridge is read, not carried** (the deferral from phase 4). The bridge block (`catalog-id-bridge.md.j2`, about 1,930 characters rendered) left the skill for the shared reference `skills/shared/catalog-id.md`, which `pipelex-design` has read since phase 4 and which includes the block unchanged. Step 1 opens with the pointer, "**For a catalog id (`mt_…`) or a published address**, read [the catalog-id reference](../shared/catalog-id.md) before reading any file", placed so that the reference's "continue just after its pointer to this file" lands on the read. The resume point was "**Step 1** below", which is where the pointer's successor now is, so the model resumes at the same place. The bridge's two guards are stated at the pointer in the words `pipelex-design` uses, and registered: "**When several directories are linked to the method, ask which is the work; never choose.**" and "**Never present a linked directory as the saved method's current content.**"
2. **The skill no longer carries the formatting-hook note** (the deferral from phase 4, decided by the same test as for `pipelex-design`). The note — every `.mthds` write triggers the validation hook, which lints, rewrites the file in canonical formatting and blocks on syntax errors; "Just write the files — don't hand-format, and re-read a file before editing it again after the hook reformatted it" — is a stop, not a guard. Edit meets the hook on a second edit of a file it has already edited, and there the harness refuses the edit of a file changed since it was read (Claude Code's Edit, Codex's `apply_patch`, Vibe's edit tool), so a model that never read the note pays one retry at most; the hook's own block names a syntax error; and "don't hand-format" costs nothing when skipped. `pipelex-organize` drops it too, so `templates/skills/shared/formatting-hook.md.j2` has no includer left; it is kept, for the reasons `classification-organize.md` gives under its behaviour change 3.

The `runs/` deferral does not reach this skill: its step 3 already submitted "`files` for every file" beside the `validate-call` include and never restated the exclusion. Step 1's "outside `runs/`" stays, because that is the set the skill *reads*, which the submission convention does not govern — `pipelex-design`'s re-entry baseline words it the same way.

Not behaviour changes, but worth a reviewer's eye:

- **The authoring reference is pointed at from step 4.** The old skill named `../shared/mthds-reference.md` only in its closing list, "read for concept definitions and syntax before editing constructs you haven't touched recently", while step 4 said "See the language reference for accepted forms". Box B puts a pointer at its condition, so step 4 opens with it; the index keeps both entries with their conditions.
- **Step 6's condition is one sentence.** The old step re-projected the template "when the edit could have changed the input template", compared keys "if an `inputs.json` exists next to the bundle", and skipped "no `inputs.json`, or an edit that cannot touch the template". The new step runs when both hold and skips otherwise, which is the same set of cases.

## For `docs/decisions.md`

These bullets join the new section **"`pipelex-edit`'s and `pipelex-organize`'s rationale, moved out of the skills (2026-09-23)"**, whose opening paragraph and first bullets `classification-organize.md` carries; the first two of its bullets — the bridge read from the shared reference and the formatting note's departure — cover edit too, and are not repeated here.

- **Edit never works on a broken baseline, because a later failure would be unreadable.** If the bundle fails validation before the change, the regressions an edit introduces and the errors that were already there become indistinguishable in the verdict after it, so the skill surfaces the old errors and offers to repair them first. The rule was already stated in "Edit vs design"; this is its reason, which the skill used to ship beside it.
- **Edit keeps the hook's fail-open posture in half a sentence.** The validation hook skips its semantic stage without an API key, so a hook that passes silently has proven nothing, and the skill declares an edit done only on `mthds_validate`'s verdict. The skill keeps "its semantic stage is skipped without an API key" beside that guard, because without it a model that has just watched the hook pass would plausibly read its silence as the verdict.
- **Edit ships no reference.** Its rename checklist is the only candidate branch, and a rename is most of what the skill does, so a pointer to it would be followed on most runs and cost more than the few lines it would move. The skill landed at about 10,400 characters on Claude, with room for later fixes.
