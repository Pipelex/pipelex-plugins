## Behaviour changes

Box G allows a phase to change behaviour only by resolving a contradiction found while consolidating. These are all of them.

1. **Preparation no longer "rewrites `inputs.json`" anywhere.** The prepare step said to write `inputs.prepared.json` and leave `inputs.json` exactly as it is (line 311), while the value-shapes section (line 377: "that rewritten form is what `inputs.json` holds from then on"), example 2 (line 411: "uploads it and rewrites `inputs.json`"), example 4 (line 457: "uploads the whole list and rewrites it to `[{"url": …}, …]`") and the User data report (line 264: "The final `inputs.json` content (after preparation)") still described the retired behaviour. This is `L-260922-e01c73`, whose own fix is PR #49; the rewrite resolves it for the prepare step's version wherever those sentences landed: example 2 in `synthetic.md` writes the run-ready form to `inputs.prepared.json` "leaving `inputs.json` as saved", example 4 in `user-data.md` says "`inputs.prepared.json` holds it as … while `inputs.json` keeps the three paths", the report lists "the final `inputs.json` content, which files were uploaded, and whether `inputs.prepared.json` was written beside it", and the value-shapes sentence is gone with its section (step 5 states the prepared file's shape once). The haiku example that saved into `methods/summarize_pdf/` (line 395), the item's other defect, was deleted with example 1 (see its row), so no example path is left to be wrong. PR #49 and this branch touch the same lines; whichever lands second takes the other's side of these sentences, which say the same thing.
2. **The readiness line no longer claims a prepared file that was never written.** "Finish" said "`inputs.json` holds the source values … and `inputs.prepared.json` beside it holds the run-ready form, with every file uploaded" (line 336) on every path, while the skip branch (line 326) writes no prepared file when every file-ish value is already remote. Step 6 now says "the run-ready form in `inputs.prepared.json` where prepare wrote one".
3. **The PDF worked example sends the path absolute.** Example 3 said "call `mthds_prepare_inputs` with the same bundle `files` and these `inputs`" (line 433), the `inputs` being the relative `inputs/invoice.pdf` the call's own rule (line 302) forbids sending. The example in `user-data.md` now says "with the same bundle `files` and these `inputs`, the path sent absolute".

Not behaviour changes, but worth a reviewer's eye:

- **The interactive additions are read with their strategy.** The "Interactive additions" (lines 47–51) were a list under the strategy table that the mode paragraph pointed at. They moved into the strategy that asks each one — which file maps to which input into `user-data.md`, the domain context and edge-case-or-happy-path into `synthetic.md`, the values or constraints on a field into both — and the mode paragraph now says "ask what the strategy's reference lists before filling anything". Each strategy reference is read at step 3, before anything is filled, which is when the old text asked them. The Template strategy fills nothing and had nothing to ask.
- **"Stay automatic on 'just do it'" is bound to the no-signal row.** Line 34 put it after both triggers for interactive mode. The first trigger is the user asking to be walked through, which a user saying "just do it" has not done, so the qualifier could only ever conflict with the second, the no-signal row with somebody to ask; the rewrite attaches it there ("somebody to ask who has not said 'just do it' or 'don't ask'").
- **An address's details are read at step 1, from a reference.** Where an address differs from an id — its default `<output_dir>`, what floating means, an invalid package, and the two prepare refusals only an address meets — is now `published-address.md`, pointed at from step 1's address bullet ("read … before the first call") and from the stop table. The instruction to say in one line that an untagged address floats stays at step 1.
- **The prepare errors are one reference.** The `input_domain` arms of the prepare verdict (lines 305–308) are one branch — prepare failed — keyed on the error's `location`, as `pipelex-integrate`'s gate failures are one reference keyed on the gate's message. The stop table keeps, on the pointer's own line, the one fact a model must not miss before reading it: "a storage size limit at `inputs` is terminal for this attempt". The file-fidelity guard that forbids working around that limit stays in `SKILL.md`, at step 5.
